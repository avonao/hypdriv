# ADR 0022 — Edge A/B experiments are flags with an `experiment` block

**Status:** accepted · **Date:** 2026-11-01

## Context

Flags already give deterministic, sticky percentage rollouts at the edge. A/B testing needs more than a rollout: named variants with weights, a record of who was exposed to what, a cache that does not show one visitor another's variant, and a way to read the outcome. The platform constraints are fixed by the rest of Hypdriv: no mandatory infrastructure (ADR 0004), the same behaviour on Workers, Vercel and Node (ADR 0013), no stored visitor identity beyond what a flag already uses.

## Decision

1. **An experiment is a flag.** `FlagDefinition.experiment` adds `variants` (weights), `traffic`, `when` (audience), `salt`, `status`, `winner` and `expose`; the flag's value is the variant and `default` is the control. Everything that works with flags (`flag()`, `useFlag()`, the `x-hypdriv-flags` header, `vary.flags`, `?hyp_flag_` QA overrides, DevTools) works with experiments, and nothing in an application changes to read one.
2. **Assignment is a pure function of `hash(stableId, name, salt)`**, so any instance reaches the same answer. A first-party cookie (`hyp_exp`, `name:variant~generation` pairs, a `*` marking a counted visitor, 180 days) keeps the assignment when `variants`, weights or `traffic` change (a ramp moves new visitors only), and remembers that the exposure was counted. The generation is a short fingerprint of `salt`: a **new `salt` voids every stored assignment**, which is what restarts an experiment (changing weights deliberately does not). The order of the checks is the contract: `concluded` (everyone gets the winner), then not-a-visitor, then the **audience before anything stored** (an old cookie cannot override a condition such as consent that no longer holds; a visitor who stops matching gets the control and loses the entry), then the stored assignment of the current generation, then `paused` (control for new visitors), then `traffic` and the weights. `experiment.when` is validated like a rule's, and an unknown condition is an error, because a typo would otherwise enrol everyone. Paused and concluded states are evaluated, not stored.
3. **Only visitors take part.** Cache warm-ups (`x-hypdriv-warm`), crawlers and preview fetchers (user agent, or the bot shield's verdict), and the owner's audit tooling (`x-hypdriv-audit`) are assigned nothing, counted never and given no cookie; a warm-up names the variant it wants in a cookie so each cached copy can be filled. A client can claim to be one of these, which only takes itself out of the test.
4. **Exposures are rows, not identities.** The flags stage reports the first page view (HTML or RSC, `GET`, 2xx, not speculative: `Next-Router-Prefetch`, `Purpose`, `Sec-Purpose`, `X-moz`, `X-Purpose: preview`) of a member once per visitor and experiment to an `ExposureSink`: Analytics Engine when bound, the log otherwise (`flags.exposures`). The row carries experiment, variant, **route pattern** (never the visited URL, which can carry a token), route id, country and build; counting rows counts visitors, so no visitor id is stored. The cookie is what remembers a visitor was counted, so an experiment it cannot hold (a name outside the cookie's token alphabet, or more than 24 per visitor) is assigned but not counted, with a warning, instead of being counted on every page view. A page the browser **prerendered** and the visitor then opened sends no request; its web-vitals beacon (`navigationType: 'prerender'`) counts the exposure and marks the cookie. A page that was only **prefetched** is counted on the visitor's next real request.
5. **Vitals are sliced at the beacon.** The vitals route reads the experiment cookie and tags the payload; the body's own `experiments` field is discarded. The Analytics Engine sink stores the tag as `blob8`, delimited at both ends so a `position()` match is exact. Exposures and vitals share one dataset, multiplexed by `blob1`, which keeps a deployment to one binding and one query credential.
6. **The cache is correct by default.** Policies (explicit and inferred) vary on every running experiment unless `vary.experiments: false`; concluded experiments drop out of the key. Responses of such policies carry `Vary: Cookie` for shared caches in front of the Worker (the engine's own lookups use a cookie-less synthetic request, so the header does not defeat it), the `hyp_uid` and `hyp_exp` cookies are added after the cache so no copy carries one visitor's `Set-Cookie`, the warmers request every variant copy of a page (control first, at most 16, marked `x-hypdriv-warm`), and a URL purge deletes every variant copy by key without needing a tag index shared between isolates. The cost is a multiplier on cached copies, which `hypdriv doctor` reports per policy and bounds (warn above 16).
7. **Vercel cannot hold one copy per variant, so it leaves those pages uncached.** Vercel's CDN keys a response by URL and `Vary` request headers only, and `Vary: Cookie` makes a response uncacheable there; a cliff-free design would need a rewrite to a per-variant path (middleware plus a prerendered page per variant), which is a routing model of its own. Until then the Vercel CDN stage refuses every policy that varies on a running experiment (reason `vary:flags`) and refuses to store any response the flags stage may set a cookie on, in `pre`, because the flags stage's `post` runs after the CDN stage's. `hypdriv doctor` names the affected policies; `vary.experiments: false` on pages that do not depend on the experiment restores CDN caching for them. Pages the platform serves as static files (`servedStatically`: Workers Static Assets, the Vercel CDN, `hypdriv serve`) are answered before Hypdriv runs and cannot take part at all; doctor lists them and warns when an experiment's `expose` names one.
8. **The report guards its own validity.** `hypdriv experiments --results` tests the observed visitors against the weights before showing any metric (p < 0.001 is a sample ratio mismatch, exit code 1 with or without `--json`), because a broken split invalidates every comparison below it. The test is Pearson's χ² while every expected count is at least 5 and an exact two-sided binomial test below that (Bonferroni over the variants when there are more than two), because χ² over-flags rare variants. The visitors of a window are compared with the weights **as they are now**, so a window that spans a ramp reads as a mismatch by construction: `--since` starts the window at the change, and a new `salt` starts a fresh experiment. It reports Core Web Vitals per variant, not business outcomes, which live in the application's analytics.

## Consequences

- No new package: the types and the cookie codec are in `@hypdriv/core`, assignment and exposure sinks in `@hypdriv/flags`, tagging and the SQL/statistics in `@hypdriv/observe`, the command and checks in `@hypdriv/cli`.
- Statistical significance of metric differences is not computed; the report is a guard against a broken experiment and a quick look at performance, not a replacement for the analysis of the business metric.
- Remote-provider experiments (KV, OpenFeature) are evaluated like local ones but are not known when the config resolves, so edge cache policies need them listed in `vary.flags`.
- EU consent for the functional cookie is the operator's call; the documented pattern is an audience rule on the consent cookie.
- The measurement is of a cooperative audience: a client that clears its cookies, sets its own `hyp_uid` or replays the public beacon can add rows to the variant it picks. What is bounded (beacon size, sampling, CORS, exposure once per cookie, no forged variants) and what is not is listed in the [flags guide](../guides/flags.md#what-is-and-is-not-protected).
- `hyp_exp` lasts 180 days from its last write (it is not refreshed on every request) and `hyp_uid` one year. A report window is at most 90 days, so no visitor is counted twice in it; an experiment that runs longer than 180 days assigns long-absent visitors again, by the same hash.

## Amendment (same day, after review)

The first version of this ADR described assignment as sticky "when weights, traffic or audience change", tested the split with χ² only, and built variant cache keys without telling shared caches about the cookie. Review found that the sticky cookie was consulted before the audience (a withdrawn consent kept a visitor in the test), that `salt` did not restart anything, that warm-ups and crawlers were counted as visitors, that `proxy.ts` never counted anyone (Next's pass-through marker is not `text/html`), that an experiment the cookie could not hold was counted on every page view, that exposure rows carried raw URLs, and that the χ² check and the exit code misbehaved. Decisions 2 to 8 above are the corrected contract; each has a test next to the code (`packages/flags/src/experiments.hardening.test.ts`, `packages/cache/src/variants.test.ts`, `packages/observe/src/vitals/experiments.test.ts`).
