# ADR 0018 — Prerenders with explicit cache tags are classified `isr`

**Status:** accepted · **Date:** 2026-10-31

## Context

The adapter classified a prerender as `static` when Next.js reported no revalidation interval (`initialRevalidate: false`), and `static` routes get a CSP built from the hashes of their build-time inline scripts ([ADR 0006](0006-csp-mode-selection.md)). The live Vercel run showed that this misses a whole class of pages: a prerender whose data carries **explicit cache tags** (`fetch(…, { next: { tags } })`, `unstable_cache(…, { tags })`, `cacheTag()`) is regenerated by `revalidateTag()` on Vercel, by OpenNext's tag cache on Cloudflare and by the incremental cache on Node. The regenerated HTML carries new inline RSC payload scripts (`self.__next_f.push(…)` with the new data), none of which match the build-time hashes, so the browser blocks them and the page stops hydrating. The audit caught it on `e2e/vercel`'s `/tagged` after a `revalidateTag('e2e-tagged')`: 5 of 8 inline scripts matched no hash. On Cloudflare the page also kept hash mode, so it was affected the same way; no check had looked at the CSP of a regenerated page before.

Next.js stores every prerender's tags in its `x-next-cache-tags` header: implicit path tags (`_N_T_/…`, present on every page) plus the explicit ones the page's data declared.

## Decision

- A prerender with at least one explicit tag (anything not prefixed `_N_T_`) is classified `isr`, like a prerender with a revalidation interval: its content can change before the next deploy. For dynamic routes, any concrete prerender with explicit tags makes the route `isr`.
- The explicit tags are recorded in the manifest (`route.prerender.tags`, at most 64) for the report, the HUD and audits.
- Nothing else changes: `isr` routes already get edge nonce injection on Cloudflare and the documented `'unsafe-inline'` fallback on Vercel and Node ([ADR 0006](0006-csp-mode-selection.md), amendment), and their caching follows the existing `isr` rules.

## Consequences

- Tag-revalidated pages keep working after `revalidateTag()` on every platform; both live suites verify that every inline script of a regenerated page is allowed by its CSP.
- On Vercel and Node these pages now carry the `'unsafe-inline'` fallback (audit grade A instead of A+). That is the honest grade: a hash policy that blocks the page after its first revalidation is not stricter, it is broken.
- A page without explicit tags that is regenerated through `revalidatePath()` still keeps hash mode; its HTML is identical when its output is deterministic. Pages whose output changes on regeneration should declare it (`revalidate`, or tags on their data), which is also what makes their caching correct.
