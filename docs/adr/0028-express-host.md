# ADR 0028 — Express: a Node response bridge for a callback middleware framework

**Status:** accepted · **Date:** 2026-11-10

## Context

ADR 0020 added Hono, a server framework whose request model (`app.fetch(request)`) is the one `createHandler()` already wraps. Express is the most widely deployed Node server framework, but its model is the opposite: middleware receives Node's `IncomingMessage` and `ServerResponse`, the app writes the response piecemeal (`writeHead`, `write`, `end`, `res.send`, `sendFile`, view engines, server-sent events), and nothing returns a `Response`. Other middleware is order-sensitive (`compression()` patches the response's writers), mount paths of routers exist only inside compiled matchers, and the platforms differ: Vercel's zero-config Express deploys the app as one Function, and Cloudflare Workers run Node HTTP servers only through `nodejs_compat`'s `httpServerHandler()`.

## Decision

1. **`@hypdriv/express` is a host over `createHandler()` with a Node bridge in `@hypdriv/runtime/node`.** The new `./node` entry turns a Node request into a Web `Request` without reading its body (a lazy body a stage can read and give back), copies the pipeline's request headers back onto the Node request, and writes a Web `Response` to a `ServerResponse` with backpressure. Fastify (ADR 0029) uses the same bridge; it is Node-only code behind its own entry point, per the runtime package rules.
2. **The middleware captures the app's response instead of buffering it.** `useHypDriv(app, { config })` / `hypdriv({ config })` patches `writeHead`, `write`, `end`, `flushHeaders` and `headersSent` on the response instance, so whatever the app writes becomes a streaming Web `Response` (a 64 KiB byte-length queue with `drain`), runs through the stages after the app, and the pipeline's response is written with the original writers. `HEAD`, `204` and `304` stay bodiless; a client that leaves stops the app's stream.
3. **The app runs inside the pipeline's request scope.** The middleware calls `next()` from the pipeline's `upstream`, so `hyp()`, `nonce()`, `flag()` and `geo()` work in every handler below it, and `res.locals.hypdrivNonce` carries the nonce for view engines.
4. **Order is checked, not guessed.** Routes, routers, mounted apps and `express.static` registered before the middleware answer without the Drivetrain; `compression()` must be registered before it (it then compresses the finished response). `checkOrder()` logs both at the first request and `hypdriv doctor` (`express.order`) reads them from the source.
5. **Static files skip the stages and keep the preset.** The default `skip` rule sends asset paths straight to the app; their responses get the security header preset (`withAssetHeaders`). Documents rendered with a nonce never get a validator-based `304`: conditional request headers are dropped from HTML navigations that carry a nonce, because Express's `ETag` describes the bytes before the nonce injection.
6. **The manifest is derived from the router stack.** Route paths use Express 5's syntax (`:id`, `*splat`, `{optional}`); mount paths are recovered by observing the compiled `path-to-regexp` expression while the matcher runs once (a synchronous, always-restored wrapper of `RegExp.prototype.exec`). Regular-expression routes and mounts are left out rather than guessed; a mounted sub-app is one `/<mount>/[[...splat]]` entry. Stale-while-revalidate renders through the app with a synthetic request (`expressFetch()`).
7. **Three platforms, verified locally.** Node (`app.listen`), Vercel (`export default app`, zero-config Express) and Cloudflare Workers (`app.listen(8080)` plus `export default httpServerHandler({ port: 8080 })` from `cloudflare:node`, with the Durable Objects re-exported). The bindings and `waitUntil` reach the handler through `cloudflare:workers`, so Workers get the exact Durable Object rate limiter and tag index.
8. **Tooling follows the other hosts.** `FrameworkName` gains `express` (detected only as a declared dependency, since Express is a common tool dependency); `hypdriv init` registers the middleware and, on Cloudflare, writes the Worker entry and wrangler settings; `hypdriv doctor` gets `express.integration`, `express.version`, `express.registered`, `express.order`, `express.vercel-entry` and `express.workers-entry`; `create-hypdriv --framework express` scaffolds `examples/express`.

## Consequences

- One more package (`@hypdriv/express`, peer `express >=5 <6`) and a new `@hypdriv/runtime/node` entry; no change to the stages or the manifest format.
- Express 4 is not supported. HTTP/2 servers are untested and unsupported.
- No build, so no static header layer, no hash-mode CSP and no budgets: the CSP is always nonce mode and caching is opt-in through policies.
- On Vercel, relative imports need `.js` (Vercel compiles each file to ESM as is) and `express.static` is ignored; on Workers, `compression()` and `express.static` stay out of the app (the request a Worker sees advertises `br, gzip` whatever the client sent, and static files belong in Workers Static Assets). The health route reports `Express unknown` where `express/package.json` is not readable at run time unless `version` is passed.
- WebSocket upgrades bypass Express middleware and therefore the Drivetrain.
- Verified locally: the package tests on Node, `examples/express` with `hypdriv audit all` and `e2e-hosts check` on Node, on workerd (`wrangler dev` with the Durable Objects) and as the Function `vercel build` produces, run in process like Vercel's Node launcher. Live Cloudflare and Vercel deployments remain pending (`docs/preview-status.md`).
