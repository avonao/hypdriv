# ADR 0019 — Vite hosts: one runtime and one build engine for every framework

**Status:** accepted · **Date:** 2026-10-31

## Context

HypDriv attached to Next.js only: `withHypDriv()`, the Adapter API, `proxy.ts` and the OpenNext Worker. Most of the code behind those attachment points was already framework-neutral — the stages, the platform assembly, the cache engine, security and observability work on Web `Request`/`Response` — but it lived inside `@hypdriv/next`, and the build-time manifest could only be produced from Next's adapter outputs. Vite-based frameworks (plain Vite apps, React Router, TanStack Start, Astro, SvelteKit, Nuxt and Cloudflare's vinext) build differently, render through their own request hooks and deploy through their own adapters, but they all end in the same three places: Cloudflare Workers (with Workers Static Assets), Vercel (Build Output API v3) and Node servers.

## Decision

1. **`@hypdriv/runtime` (neutral)** holds the Drivetrain stages, `createPlatform()`, the platform wiring per deploy target (`platformFor()`: Vercel services, Cloudflare Durable Object stores), the routing-middleware runner (`createProxyHandler()`, used by Next.js `proxy.ts` and HypDriv's Vercel Routing Middleware) and **`createHandler()`**: the runner for hosts that own the full response. It wraps any Web fetch handler (`handler(request, { upstream, env, waitUntil, cf })`), answers `/_hypdriv/*`, upgrades plain HTTP, skips build assets, runs the pipeline with `runner: 'host'`, installs the `AsyncLocalStorage` context so `hyp()` works anywhere below it, and passes through when an outer HypDriv runner (the Worker shell) already ran the stages. `@hypdriv/next/stages` re-exports the runtime; the Cloudflare shell depends on it instead of `@hypdriv/next` and accepts any application worker (`createWorker({ app })`).
2. **`@hypdriv/build` (Node)** holds the manifest assembly (`assembleManifest()`): client assets per route, CSP hashes of prerendered documents, Early Hints, the speculation graph, Purser verification, the secrets scan, weights and budgets, the fingerprint and inferred cache policies. The Next.js adapter classifies its outputs and calls it; Vite integrations discover routes and documents and call it through `finalizeManifest()`. It also computes **static header rules** (`staticHeaderRules()`) — the security preset, the hash CSP of each prerendered document, Early Hints and immutable caching — and renders them for Cloudflare `_headers` and Vercel Build Output routes.
3. **`@hypdriv/vite`** is the plugin for plain Vite apps and the toolkit every framework integration is built from: `hostPlugin()` (config loading, the `virtual:hypdriv/config` and `virtual:hypdriv/manifest` modules), route pattern converters (React Router, TanStack Router, Vue Router, SvelteKit → HypDriv's canonical `[param]` syntax), `finalizeManifest()`, the platform writers and `patchRuntimeManifest()`.
4. **The runtime manifest is patched after the build.** Server bundles are built before prerendering finishes (and on Cloudflare before the client), so `virtual:hypdriv/manifest` embeds the manifest as one JSON string literal tagged with a sentinel key. When the build — prerendering and the framework's adapter included — is complete, the integration finalises the manifest and rewrites that literal in every built server file (`patchRuntimeManifest()`), wherever the adapter copied or re-bundled it.
5. **Static responses get their posture from the platform's static configuration.** Prerendered pages and assets are served without application code on Cloudflare (Workers Static Assets) and Vercel (the CDN); HypDriv writes `_headers` (merged with the framework's and the user's, within Cloudflare's 100-rule limit, `.vite`/`.hypdriv` kept out of the upload) and Build Output `config.json` header routes (before `handle: filesystem`). A static rule carries `x-hypdriv-csp`, so when a Worker fetches the asset itself the request's policy replaces it instead of being treated as the application's. A single-page app's shell policy goes on the catch-all rule and is detached from the other rules, so no response carries two policies.
6. **Each framework integrates at its own documented request hook**, owning the full response: React Router root `middleware`, TanStack Start global request middleware, Astro middleware (`order: 'pre'`), SvelteKit `handle`, Nuxt/Nitro server middleware and render hooks, vinext `proxy.ts`. On Cloudflare, frameworks whose Worker entry the application owns use `createWorker({ app })` for `scheduled` / `queue` / Durable Objects; the in-app hook passes through inside it. Plain Vite apps get `assetsWorker()` (Cloudflare), a Build Output with HypDriv's Routing Middleware (Vercel) and `hypdriv serve` (Node).
7. **CSP nonces reach every runner that owns the body.** With `HTMLRewriter` (workerd) the `csp` stage injects nonces as before; elsewhere a portable streaming tokenizer (`injectNonceStream()`, quote-, comment- and raw-text-aware) does the same. Frameworks that apply a nonce themselves (React Router `ServerRouter`, TanStack `ssr.nonce`, vinext) get it from the request context; the injection is idempotent. Frameworks with their own policy (SvelteKit `kit.csp`, Astro `security.csp`) keep it: the stage never overrides an application policy.
8. **Vercel caches what the function says.** Inside a Vercel Function the response is the function's own, so the Vercel CDN stage applies every page policy (`vary` included) when it runs in `createHandler` (`responseOwner`), unlike Routing Middleware.

## Consequences

- One stage list, one manifest format (`framework` records the producer; `nextVersion` is Next-only), one CLI: `routes`, `manifest`, `audit`, `budget`, `csp` work for every host.
- New hosts follow a fixed recipe: discover routes, find prerendered documents, call `finalizeManifest()`, patch the runtime manifest, write static headers, wrap the framework's request hook with `createHandler()`.
- The manifest the server reads during development and before patching lists routes without prerender data; prerendered pages are served statically with their static rules in the meantime.
- Static header rules depend on platform semantics HypDriv cannot verify at build time (Cloudflare's rule limits, Vercel's route merging); the live suites check them on real deployments.
