# ADR 0026 — Placeholders have a portable engine: built-in decoders, optional WebAssembly codecs

**Status:** accepted · **Date:** 2026-11-01

## Context

`generatePlaceholders()` needed `sharp`, a native module. CI images, locked-down build hosts and minimal containers often cannot install or run one, and the function answered `skipped: 'sharp-missing'`: no placeholders, silently, in exactly the environments that ship to production. A zero-infrastructure baseline (ADR 0004) should hold for the build step too. The inputs are the images in `public/`: mostly JPEG and PNG, some GIF, increasingly WebP and AVIF. The output is a 16-pixel picture.

## Decision

1. **Two engines behind one function.** `engine: 'auto'` (default) uses `sharp` when it resolves and the portable engine otherwise; `'sharp'` and `'portable'` force one. A missing optional engine never throws; it returns `skipped` with the package to install.
2. **The portable engine decodes in TypeScript.** PNG (every color type and bit depth, Adam7, `tRNS`), GIF (first frame) and JPEG (baseline, extended sequential and progressive Huffman; any subsampling; restart intervals; grayscale, YCbCr, RGB, CMYK, YCCK) are small, well specified and cheap to decode into a 16-pixel result, so no dependency is needed. Arithmetic-coded, lossless and 12-bit JPEGs are rejected with a clear error.
3. **Decoders stream into an area-average downscaler.** Rows go straight into a coverage-weighted, alpha-premultiplied accumulator the size of the placeholder, so a large PNG never exists as a full RGBA bitmap. The PNG is inflated through a back-pressured stream, one scanline at a time (a 4096 × 4096 picture holds about 3 MB, not its 16 MB raster), and an interlaced one delivers its Adam7 passes as sparse rows; if the file ends early the pixels never delivered simply do not count, so a truncated picture is not darkened or faded.
4. **Big JPEGs are decoded from their DC coefficients.** A block's DC value is the exact mean of its 8×8 pixels, so the target is reached without an IDCT and progressive files skip every AC scan. This is what libjpeg's reduced-size decoding does, and so what sharp's shrink-on-load does; `accuracy: 'exact'` forces the full decode. Pictures under eight times the placeholder always take the full path, whose output matches libjpeg to within a level or two (fancy chroma upsampling included).
5. **WebP and AVIF come from optional WebAssembly codecs.** Writing a VP8/AV1 decoder in TypeScript is not proportionate; `@jsquash/webp` and `@jsquash/avif` are compiled once from the file and initialised explicitly (their default loader uses `fetch`, which does not work in Node), resolved from the project first. Without them those files are `unsupported` (reported, not failed). With `@jsquash/webp` the placeholder is a WebP; without it, a PNG written by a 100-line encoder (adaptive filters, level-9 deflate, a few hundred bytes), which `blurDataURL` accepts like any `data:image/*`.
6. **Hostile and broken files are bounded before anything is allocated.** Header probes (`inspectPortable`; PNG, GIF, JPEG, and the WebP `VP8X`/`VP8`/`VP8L` and AVIF `ispe` boxes) refuse impossible dimensions, more than 2²⁰ pixels per side, more than `maxPixels` (134 million) and a decode whose estimated working set exceeds `maxMemory` (1 GiB) before a decoder runs, so a 16,000 × 8,000 header cannot make a build host swap. A `MemoryBudget` admits parallel decodes by their estimates, so a pool of workers cannot add up to more than the budget either (one bigger picture runs alone). Placeholders are at most 64 times taller than wide. A JPEG whose entropy data ends early stops after 16 empty groups instead of decoding the empty remainder of a lying header, and more than 256 scans is refused. Animated WebP is decoded from its first frame, cut out as a still file.
7. **Colour follows libjpeg.** JFIF means YCbCr, then the Adobe marker, then component ids (`R`, `G`, `B`); CMYK and YCCK are decided by the Adobe transform; missing component scans decode as neutral, and full-resolution chroma uses the same centred "fancy" upsampling (restricted to the cases libjpeg interpolates).
8. **The file records how it was made.** `engine`, `format`, `quality` (and `accuracy` for the portable engine) join `size` in `.hypdriv/placeholders.json`, and every entry carries a content hash next to its size and mtime. A run with different settings regenerates; a run with the same settings reuses entries whose size and mtime match, or whose hash matches when only the mtime moved (a git checkout resets them all); entries made by another engine are reused under `engine: 'auto'` unless the engine or format is pinned; nothing is rewritten when nothing changed.
9. **Fixtures come from independent decoders.** The tests compare against Pillow/libjpeg/ImageMagick output (`__fixtures__/generate.py` regenerates the files and the reference), including real WebP/AVIF through the actual codecs, and against sharp when it is installed.

## Consequences

- Placeholders work on any Node >= 20.9 without native code; `hypdriv placeholders --check` can gate CI on them.
- About 2,000 lines of decoder, probe and budget code live in `@hypdriv/image/node` and must be maintained; the surface is frozen formats and the fixture suite is the safety net.
- The DC-only path is an approximation near sharp colour edges of chroma-subsampled pictures (visible only as a slightly different 16-pixel blur); `accuracy: 'exact'` is the escape hatch.
- Animated images use their first frame; ICC profiles and EXIF orientation are ignored, as with the sharp path.
