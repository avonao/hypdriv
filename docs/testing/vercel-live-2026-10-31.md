# Live Vercel test — 2026-10-31

HypDriv tested on a real Vercel team on the **Hobby** (free) plan, US-first: every function and the Routing Middleware run in `iad1` (requests reached it through the Cleveland edge, `x-vercel-id: cle1::iad1::…`). Everything created for the test is named `avonao-hypdriv-dev*`; Vercel has no resource tags, so every deployment carries the `tag=hypdriv-dev` deployment meta and the DNS records a `hypdriv-dev:` comment. The team token was used only from the operator's shell and by the suite's runner; the deployments hold project secrets and a Global Config **read** token, never the account token.

## Defects found and fixed

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| 1 | high | A prerender with explicit cache tags (`unstable_cache(…, { tags })`) was classified `static` and kept build-time CSP hashes; after `revalidateTag()` its regenerated inline RSC payload scripts matched none of them (5 of 8 blocked), so the page stopped hydrating. Affected Cloudflare as well. | Explicit tags (from Next's `x-next-cache-tags`, minus the implicit `_N_T_` ones) make a prerender `isr`: edge nonces on Cloudflare, the declared fallback on Vercel ([ADR 0018](../adr/0018-tag-revalidated-prerenders.md)). Both suites check every script of a regenerated page against its CSP. |
| 2 | high | `revalidatePath()` / `revalidateTag()` / `purgeEdge()` called from a Route Handler or Server Action did not purge HypDriv's CDN tags: the purger was registered only by `createProxy`, and Routing Middleware runs in a separate invocation from Vercel Functions. Live: a `withVercelCdn` response stayed a HIT after `revalidatePath()`. | `createInstrumentation().register()` registers the Vercel CDN purger in functions; `path:` tags also purge the CDN's `hyp:path:` tags (no request URL needed); the repeat purge runs under Vercel's `waitUntil`. |
| 3 | high | Outbound requests could hold a function until its time limit (observed: 230–300 s, then 504): Next.js tees `fetch` bodies and a teed body's `cancel()` never settles while the other branch is unread; HypDriv awaited body cancels in `hypFetch` retries, `enqueue()`'s inline consumer call and cache warming, and `hypFetch`'s timeout depended on the fetch implementation honouring the abort signal. | Body cancels are fire-and-forget; the timeout and the caller's abort settle each attempt themselves (`E_TIMEOUT`), and a response that arrives late is released. Regression tests use bodies whose cancel never settles. |
| 4 | medium | Pages matched by a policy with `vary` (no route-header form on Vercel) were reported as `x-hypdriv-cache: CDN` although Vercel cannot cache them per variant; the audit failed them as a broken cache. | The proxy reports them as `BYPASS` with `x-hypdriv-cache-reason: route-header:vary` (also `route-header:pattern:…`); the build warns; `hypdriv audit cache` reports a platform limit as a warning. Route Handlers get per-country entries through `withVercelCdn`. |
| 5 | medium | `jobHandler` ignored `vercel.cronSecretEnv` and `security.internalAuth.secretEnv`, and a cron call without `x-vercel-cron-schedule` reached the job without its schedule. | Secret env names come from the registered config; job name and schedule from the `jobs.cron` entry for the path. |
| 6 | low | `/_hypdriv/health` reported `deployment: null` on Vercel (no Next.js `deploymentId` without Skew Protection). | Falls back to `VERCEL_DEPLOYMENT_ID`. |
| 7 | low | Health did not show whether Global Config or Upstash was detected. | New `config store` line (Global Config / Upstash Redis / Workers KV / none). |
| 8 | low | Web Vitals beacons logged by the proxy had no country on Vercel (only `request.cf` was read). | The proxy passes the country from the edge headers (`x-vercel-ip-country`, `cf-ipcountry`). |
| 9 | low | In monorepos `vercel link` / `pull` / `build` run at the repository root, so `doctor`, `analyze` and the audit's secret lookup did not see the pulled env files or `.vercel/output`. | The repository root's link counts for the app named as its root directory. |
| 10 | low | `vercel.botId` was documented as "verdicts in the bot stage", which no stage implements. | Documented as what it is: the default check level of `botIdGuard()`; the guide covers BotID end to end. |
| 11 | low | The package build printed rolldown's `MODULE_LEVEL_DIRECTIVE` warning for six `'use client'` modules; the directive survived, but nothing guaranteed it. | A build plugin keeps `'use client'` on every client entry chunk, fails the build if a client module lands anywhere else, and filters the now-redundant warning: the build is warning-free. |

## Observations (no change needed)

- **Runtime logs** are a live stream only (`GET /v1/projects/{id}/deployments/{id}/runtime-logs`): no history, 15–20 s to connect at times, and best-effort under bursts (about a third of the lines of a 60-request burst never arrived). The runner opens the stream before the first check, waits for a probe request to show up, and re-triggers an action whose log line is missing; Hobby has no log drains.
- Routing Middleware and Functions share the SDK registrations made in `instrumentation.ts` (the WAF stage in the proxy used `checkRateLimit` registered there).
- Without Upstash, rate-limit counters are per instance; Fluid compute spread eight sequential requests over two instances (`200×5, 429, 200, 429`).
- The WAF rule's fixed window counts per region; the policy's 429 carries HypDriv's `Retry-After`.
- Headless Chromium is classified as a bot by BotID, and its `HeadlessChrome` user agent is blocked on documents by HypDriv's shield before BotID is consulted; the browser check uses a regular Chrome user agent and verifies that `initBotId()` attaches `x-is-human`.
- Vercel Queues has no dead-letter queue; the e2e app uses `retry: 'none'` to show acknowledgement instead.
- Environment variables are bound per deployment: switching Turnstile keys needs a redeploy (on Cloudflare a secret change suffices).
- Next.js serves `x-vercel-cache: PRERENDER` for the first RSC request of a prerendered page and HTML from `HIT`; the RSC and HTML entries never mix.
