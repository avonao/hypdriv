New package: Hypdriv for SolidStart 2 (Solid on Vite 8, deployed through Nitro 3 or `@cloudflare/vite-plugin`) on Cloudflare Workers, Vercel and Node. `hypdriv()` from `@hypdriv/solid-start/vite`, listed after `solidStart()` and the deployment plugin, registers a Nitro module whose runtime plugin wraps `nitroApp.fetch` with the Drivetrain (Node, Vercel, Nitro-built Workers; Nitro's prerender build is left alone, so static documents never carry a request's nonce) and, after the complete build, writes the route manifest from `src/routes` (per-route assets from the client Vite manifest), the CSP hashes of Nitro-prerendered pages, the static headers (Cloudflare `_headers`, Vercel Build Output routes, clean-URL overrides and Routing Middleware, Nitro route rules for a Node server's hashed assets) and the final manifest in every server output. `hypdrivStart()` passes the request's CSP nonce to Solid's renderer through `createHandler()`; the CSP stage nonces anything left. With `@cloudflare/vite-plugin`, `createSolidStartWorker()` from `@hypdriv/solid-start/cloudflare` is Hypdriv's Worker shell around the server entry (Durable Objects, `scheduled` / `queue` / `email` handlers, worker-first public files). `@hypdriv/solid-start/server` provides `hyp()`, `nonce()`, `flag()`, `geo()`, `defer()` and `jobHandler()` for API routes, server functions and server-side loaders. `hypdriv init` registers the plugin and the nonce option (and adds the Cloudflare plugin, Worker entry and wrangler settings), `hypdriv doctor` gets the `solid-start.version`, `.deployment-plugin`, `.plugin-order`, `.cloudflare-plugin`, `.worker-entry`, `.entry-nonce` and `.prerender` checks, `create-hypdriv --framework solid-start` scaffolds `examples/solid-start` for any platform, and `@hypdriv/core`'s `FrameworkName` gains `solid-start`.
