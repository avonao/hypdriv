New package: Hypdriv for vinext (Cloudflare's Vite implementation of the Next.js API). The `hypdriv()` Vite plugin wraps vinext's App Router request handler with `createHandler()` on every runtime (`vinext start`, Cloudflare Workers, Nitro on Vercel and Node, `vite dev`), so the Drivetrain owns every response and application code reads `hyp()`; vinext's build-time prerender bypasses it through a random per-build token in the build's environment. After vinext's prerender and the platform output it writes `.hypdriv/manifest.json` (routes from `app/` and `pages/`, hash CSPs for the prerendered pages the platform serves as built, `isr` for pages vinext caches at run time with the nonce injected into the cached HTML), patches the final manifest into every server output and writes Cloudflare `_headers` or Vercel Build Output routes; on Vercel the prerendered static pages are served from the CDN. Also: `createVinextWorker()` (Worker shell with `scheduled` / `queue` / Durable Objects), `createProxy()` for Pages Router apps, `withHypDrivCache()` so `revalidateTag()` / `revalidatePath()` purge Hypdriv's edge cache, and the server helpers as dynamic APIs.
