New package: Hypdriv for RedwoodSDK (`rwsdk` 1.x, React Server Components on Vite) on Cloudflare Workers, the only platform RedwoodSDK targets. `export default withHypDriv(defineApp([hypdrivMiddleware(), …]))` in the Worker entry puts the Drivetrain (`createWorker()` with `HTMLRewriter`, Durable Object stores, Hypdriv's `scheduled` / `queue` / `email` / `tail` jobs next to your own handlers) around every request, answers public files from the assets binding first and keeps `defineApp`'s `__rwRoutes`. `hypdrivMiddleware()` hands the nonce of Hypdriv's CSP to RedwoodSDK (`rw.nonce`), which puts it on its RSC payload and hydration scripts; without it a nonce CSP blocks them, and the Worker, the build and `hypdriv doctor` report that. The route manifest is read from the running app's own routes (exact) and, at build time, from the Worker's source (array literals, imported route arrays, `tsconfig` paths); computed routes go in the plugin's `routes` option. The `hypdriv()` Vite plugin (after `redwood()`) serves the config and manifest to the Worker, exports the Durable Object classes from the Worker entry and, after RedwoodSDK's multi-pass build, writes `.hypdriv/manifest.json`, patches it into `dist/worker` and writes `dist/client/_headers` for the hashed assets. `@hypdriv/rwsdk/server` provides `hyp()`, `nonce()`, `flag()`, `geo()`, `defer()` and `jobHandler()` for server components, server functions and route handlers. `hypdriv init` wraps `defineApp` and registers the plugin (and writes the Wrangler settings), `hypdriv doctor` gets the `rwsdk.worker-entry`, `rwsdk.nonce-middleware`, `rwsdk.cloudflare-plugin`, `rwsdk.plugin-order`, `rwsdk.platform` and `rwsdk.version` checks, `create-hypdriv --framework rwsdk` scaffolds `examples/rwsdk` (Cloudflare only), and `@hypdriv/core`'s `FrameworkName` gains `rwsdk`.
