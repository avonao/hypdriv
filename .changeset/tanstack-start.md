New package: HypDriv for TanStack Start (React) on Cloudflare Workers, Vercel and Node (ADR 0019). `hypdrivRequestMiddleware()` registers the Drivetrain as Start's global request middleware (SSR documents, server routes, server functions, not-found pages, redirects), followed by Start's CSRF protection for server functions, which a custom `src/start.ts` would otherwise switch off; the request's CSP nonce reaches the router through `hypdrivSsr()` (`ssr.nonce`), and `hyp()`, `flag()`, `nonce()`, `geo()`, `defer()` and `jobHandler()` work in server functions and server routes (`@hypdriv/tanstack-start/server`). The `hypdriv()` Vite plugin discovers routes with TanStack's generator (without writing to the project), finalises the manifest after Start's prerendering (per-route assets, CSP hashes, Early Hints), patches it into `dist/server`, `.output/server` or `.vercel/output/functions`, and writes Cloudflare `_headers`, Vercel Build Output header routes and clean-URL overrides, or Nitro `routeRules` for a Node server's hashed assets. `withHypDriv()` marks Start's prerender requests with a per-build token that is removed from the server output afterwards, so static documents never carry a request's nonce. On Cloudflare, `createStartWorker()` runs Start inside HypDriv's Worker shell (`scheduled`, `queue`, `email`, Durable Objects); `@hypdriv/tanstack-start/server-entry` offers the outer `src/server.ts` wrapper for Node and Vercel. Browsers resolve the package to inert stand-ins, keeping the runtime and the config out of the client bundle.
