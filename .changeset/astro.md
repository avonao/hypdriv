New package `@hypdriv/astro`: HypDriv for Astro 7 on Cloudflare Workers, Vercel and Node. The `hypdriv()` integration registers Astro middleware (`order: 'pre'`) that runs the Drivetrain around every on-demand route through `createHandler()`, with `hyp()` available in pages, components, endpoints, server islands and actions (`@hypdriv/astro/server`, plus `jobRoute()` for signed jobs and Vercel Cron). Build-time prerendering never runs the pipeline: Astro's prerender bundle gets a compile-time `prerendering` flag through `virtual:hypdriv/astro`. Astro's error-page pass (a render that threw → `500.astro`, an empty 404/500 → the error page) reapplies the response stages without counting the request against rate limits or the bot shield again. After the adapter, the build writes the manifest (routes from `astro:routes:resolved`, CSP hashes of every prerendered document, Early Hints), Cloudflare `_headers`, Vercel Build Output header routes (including the 404 catch-all) or `@astrojs/node`'s `_headers.json`, and patches the final manifest into the server output. `/_hypdriv/*` reaches HypDriv through an injected on-demand route; `withHypDriv()` (`@hypdriv/astro/fetch`) wraps `src/fetch.ts` to cover unmatched URLs and config redirects; on Cloudflare `createWorker({ app })` wraps `@astrojs/cloudflare/handler` for Durable Objects and `scheduled`/`queue` handlers. With Astro's `security.csp` enabled, Astro owns the policy and HypDriv's CSP is switched off for the app.
